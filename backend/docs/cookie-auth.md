# Staged cookie authentication rollout

1. Merge and deploy both applications with existing settings. Legacy bearer authentication is unchanged by default.
2. Generate a new secret locally: python -c "import secrets; print(secrets.token_urlsafe(48))". Set the exact same STORE_PROXY_SECRET in Vercel backend Production and Cloudflare Pages Functions Production secrets (not VITE_ variables). Never commit or share it. Set COOKIE_AUTH_ORIGINS=https://e-commerce-3q5.pages.dev in Vercel. Redeploy both.
3. Verify https://e-commerce-3q5.pages.dev/api/products/ returns JSON. Set VITE_COOKIE_AUTH=true in the Cloudflare Pages production build environment and redeploy. Local Vite development remains bearer-based until the optional local migration is implemented.
4. Test customer/admin separately and together, reload, logout each role, remember-me, cart, checkout, payment, image uploads, password reset, expired session, 429, and verify the cookie flags in DevTools Application. Browser storage must not contain access tokens. Check that requests are same-origin /api and no JWT is returned by session/login. Use a fresh rate-limit window. Cookies last no longer than existing JWT expiration; logout removes the cookie, not a copied JWT from server-side storage.
5. Only after production browser tests succeed, set DISABLE_BEARER_AUTH=true in Vercel and redeploy. This disables direct bearer clients including local development against production. To roll back, first re-enable bearer authentication in Vercel, then unset VITE_COOKIE_AUTH in Cloudflare and redeploy.

CSRF uses a strict allowed Origin check for unsafe cookie-authenticated requests and login/logout, plus a required custom session-role header and host-only Secure HttpOnly SameSite=Lax cookies. No token is exposed to frontend JS. The gateway forwards only approved headers, attaches its own secret and Cloudflare client IP, prevents cross-origin redirects and disables caching. Keep CSP enforced. A stolen session token remains usable until expiration; server-side revocation is a separate improvement. Same-origin XSS can still perform actions. No schema migration required. Do not set DISABLE_BEARER_AUTH until testing is complete.
